# ADR 0005 — Timestamp and Timezone Policy

## Status

Accepted (Finalized in Step 03)

---

## Context

Zero Brokerage is a distributed real estate platform with multi-region users, brokers, administrative staff, background workers, and external integrations. Operations such as listing publication, session timeouts, OTP expiration, audit logging, outbox dispatching, and visit scheduling depend critically on temporal accuracy.

Storing timestamps without timezone awareness (`TIMESTAMP WITHOUT TIME ZONE`) or using localized server time zones introduces severe defects:
1. **Clock Ambiguity**: A timestamp such as `2026-10-01 10:00:00` without timezone metadata is ambiguous. It represents completely different instants in time in New Delhi (UTC+05:30), London (UTC+00:00), or New York (UTC-04:00).
2. **Broken Distributed Ordering**: Comparing timestamps generated by servers with different system clocks or timezone configurations produces non-deterministic sorting in event logs, outbox tables, and keyset pagination.
3. **Client Clock Skew**: Relying on timestamps sent from mobile devices or browser clients opens security vulnerabilities (e.g., tampering with device clock to bypass OTP expiration or trial periods).

---

## Decision

Zero Brokerage adopts a strict, non-negotiable timestamp and timezone architecture:

### 1. Storage Type Standard: PostgreSQL `TIMESTAMPTZ`
- Every temporal column representing an instant in time MUST use PostgreSQL **`TIMESTAMPTZ`** (timestamp with time zone).
- Plain `TIMESTAMP WITHOUT TIME ZONE` and `TIME` are strictly prohibited for temporal event storage.
- PostgreSQL internally stores `TIMESTAMPTZ` values as absolute UTC timestamps (microseconds since 2000-01-01 00:00:00 UTC).

### 2. Universal Canonical Timezone: UTC
- **Storage Timezone**: Always UTC. All database connection pools, server environments, container runtimes, and CI/CD pipelines run with `TZ=UTC`.
- **Query & Comparison Timezone**: Always UTC. All SQL `WHERE` clauses, index comparisons, lease calculations, and keyset pagination cursors evaluate in UTC.
- **Display / Presentation Timezone**: Timezone translation occurs exclusively at the client presentation boundary (e.g. mobile app, web dashboard) based on the user's geographical locality (defaulting to Indian Standard Time, `Asia/Kolkata` / UTC+05:30, for domestic platform users).

### 3. Server-Authoritative Timestamp Generation
- Timestamps for security, lifecycle, and data mutation decisions must ALWAYS be generated server-side.
- Database default: `TIMESTAMPTZ NOT NULL DEFAULT NOW()`.
- Application runtime: Native JavaScript `new Date()` (which represents UTC epoch milliseconds).
- Timestamps supplied by client HTTP requests must NEVER be trusted for authorization, expiration, or ordering.

## Standard Timestamp Columns & Semantics

| Column Name | Type | Nullability | Purpose & Lifecycle Behavior |
| :--- | :--- | :--- | :--- |
| **`created_at`** | `TIMESTAMPTZ` | `NOT NULL DEFAULT NOW()` | Immutable record creation timestamp. Never updated after row insertion. |
| **`updated_at`** | `TIMESTAMPTZ` | `NOT NULL DEFAULT NOW()` | Mutation timestamp. Updated automatically by repositories on every write operation. |
| **`expires_at`** | `TIMESTAMPTZ` | `NOT NULL` / `NULL` | Absolute instant at which an authorization token, OTP challenge, or commercial placement expires. |
| **`available_at`** | `TIMESTAMPTZ` | `NOT NULL DEFAULT NOW()` | Outbox / task scheduling timestamp indicating when an event becomes eligible for worker claiming. |
| **`claimed_at`** | `TIMESTAMPTZ` | `NULL` | Timestamp when an asynchronous worker claimed an outbox event lock. Reset to `NULL` upon lease release. |
| **`processed_at`** | `TIMESTAMPTZ` | `NULL` | Timestamp when an outbox event or background job successfully completed publication. |
| **`occurred_at`** | `TIMESTAMPTZ` | `NOT NULL DEFAULT NOW()` | Domain event occurrence timestamp. Captures the exact business instant an event happened, distinct from insertion time. |
| **`verified_at`** | `TIMESTAMPTZ` | `NULL` | Instant when an administrator or automated system approved a broker license or verified a listing. |
| **`deleted_at`** | `TIMESTAMPTZ` | `NULL` | Soft-delete timestamp indicating when an entity transitioned to a deactivated/soft-deleted state. |
| **`deletion_scheduled_at`** | `TIMESTAMPTZ` | `NULL` | Scheduled permanent purge timestamp for account retention workflows. |

## Implementation Rules in Application & Repositories

1. **Driver Configuration**:
   - The PostgreSQL client pool (`pg`) is configured to parse `TIMESTAMPTZ` directly into JavaScript native `Date` objects in UTC.
2. **API Contract Serialization**:
   - In HTTP and JSON payloads, all timestamps MUST be serialized according to ISO 8601 / RFC 3339 format with explicit UTC zero offset indicator `Z`:
     ```json
     "createdAt": "2026-09-30T04:22:27.123Z"
     ```
   - Localized offsets (e.g. `+05:30`) in internal API payloads are avoided in favor of standard `Z` notation.
3. **Date Arithmetic & Intervals**:
   - Interval arithmetic in SQL queries must use PostgreSQL native intervals or explicit millisecond math in TypeScript:
     ```sql
     -- Safe SQL interval arithmetic
     WHERE available_at <= NOW()
       AND claimed_at < NOW() - ($1 || ' seconds')::INTERVAL
     ```
4. **Hardware & Infrastructure Clock Synchronization**:
   - All production host virtual machines, containers, and database nodes MUST run Network Time Protocol (NTP) daemons (such as `chrony` or `systemd-timesyncd`) synchronized to authoritative Stratum 1 time servers to eliminate clock drift.

---

## Consequences

- **Positives**:
  - Deterministic and monotonic event ordering across micro-services, background workers, and databases.
  - Zero bugs associated with Daylight Saving Time or arbitrary server timezone discrepancies.
  - Clean audit trails for legal compliance, regulatory reporting, and security forensics.
- **Trade-offs**:
  - Display formatting requires explicit timezone mapping in client applications when rendering human-readable dates (e.g. `Intl.DateTimeFormat('en-IN', { timeZone: 'Asia/Kolkata' })`).
